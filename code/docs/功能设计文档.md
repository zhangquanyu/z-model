# Z-Model 模型管理系统 - 功能设计文档

## 1. 功能概述

Z-Model 模型管理系统是一个用于创建和管理业务模型的平台，核心功能围绕**需求管理**、**模型管理**、**属性管理**、**方法管理**、**事件管理**和**业务流程建模**六大模块展开。

系统核心规则：
1. **先建需求**：创建模型前必须先创建并审批通过需求
2. **需求关联**：创建属性及方法时必须关联对应的需求
3. **参数选择**：方法的出参与入参必须从已创建的属性中选择

---

## 2. 功能模块设计

### 2.1 需求管理模块

#### 2.1.1 功能概述

需求管理是整个系统的起点，所有模型的创建都必须基于已审批通过的需求。

#### 2.1.2 功能点

| 功能点 | 描述 | 操作路径 |
|--------|------|----------|
| 需求列表 | 展示所有需求，支持按状态、优先级筛选 | /requirements |
| 创建需求 | 创建新的需求，填写名称、描述、优先级等信息 | /requirements/create |
| 编辑需求 | 修改已有需求的基本信息 | /requirements/{id}/edit |
| 删除需求 | 删除未关联模型的需求 | /requirements/{id}/delete |
| 需求审批 | 审批需求，变更需求状态 | /requirements/{id}/approve |
| 需求详情 | 查看需求详情及关联的模型、属性、方法 | /requirements/{id} |

#### 2.1.3 需求状态流转

```
DRAFT (草稿)
    │
    ├─→ 提交审批 ──→ PENDING (待审批)
    │                     │
    │                     ├─→ 审批通过 ──→ APPROVED (已批准)
    │                     │
    │                     └─→ 审批拒绝 ──→ REJECTED (已拒绝)
    │
    └─→ 直接删除
```

#### 2.1.4 需求优先级

| 优先级 | 标识 | 说明 |
|--------|------|------|
| LOW | 低 | 普通功能需求 |
| MEDIUM | 中 | 重要功能需求 |
| HIGH | 高 | 核心功能需求 |
| CRITICAL | 紧急 | 紧急修复需求 |

#### 2.1.5 业务规则

1. **审批规则**：只有状态为 `PENDING` 的需求才能进行审批操作
2. **删除规则**：已关联模型的需求不允许删除
3. **编码规则**：需求编码自动生成，格式为 `REQ-XXX`
4. **关联规则**：只有 `APPROVED` 状态的需求才能被模型、属性、方法关联

### 2.2 模型管理模块

#### 2.2.1 功能概述

模型是属性和方法的容器，每个模型必须关联至少一个已审批通过的需求。

#### 2.2.2 功能点

| 功能点 | 描述 | 操作路径 |
|--------|------|----------|
| 模型列表 | 展示所有模型，支持搜索筛选 | /models |
| 创建模型 | 创建新模型，关联已审批的需求 | /models/create |
| 编辑模型 | 修改模型基本信息和关联需求 | /models/{id}/edit |
| 删除模型 | 删除模型及其关联的属性和方法 | /models/{id}/delete |
| 模型详情 | 查看模型的完整信息，包括属性和方法列表 | /models/{id} |
| 关联需求 | 为模型添加或移除关联的需求 | /models/{id}/requirements |

#### 2.2.3 业务规则

1. **需求关联规则**：模型必须关联至少一个 `APPROVED` 状态的需求
2. **编码规则**：模型编码自动生成，格式为 `MODEL-XXX`
3. **删除规则**：删除模型会级联删除其关联的属性、方法和方法参数

---

### 2.3 属性管理模块

#### 2.3.1 功能概述

属性是模型的数据结构定义，属性的数据类型决定了其在方法参数中的使用方式。

#### 2.3.2 功能点

| 功能点 | 描述 | 操作路径 |
|--------|------|----------|
| 属性列表 | 展示指定模型下的所有属性 | /models/{id}/properties |
| 创建属性 | 创建新属性，选择所属模型和关联需求 | /models/{id}/properties/create |
| 编辑属性 | 修改属性信息 | /models/{id}/properties/{id}/edit |
| 删除属性 | 删除属性，会级联删除关联的方法参数 | /models/{id}/properties/{id}/delete |

#### 2.3.3 数据类型

| 数据类型 | 说明 | 示例 |
|----------|------|------|
| STRING | 字符串类型 | "hello world" |
| INTEGER | 整数类型 | 100 |
| LONG | 长整数类型 | 10000000000 |
| DOUBLE | 浮点数类型 | 3.14 |
| BOOLEAN | 布尔类型 | true/false |
| DATE | 日期类型 | 2024-01-01 |
| DATETIME | 日期时间类型 | 2024-01-01 12:00:00 |
| ENUM | 枚举类型 | ["PENDING", "PAID", "SHIPPED"] |
| OBJECT | 对象类型 | {"key": "value"} |
| ARRAY | 数组类型 | [1, 2, 3] |

#### 2.3.4 业务规则

1. **需求关联规则**：创建属性时必须关联一个 `APPROVED` 状态的需求
2. **模型归属规则**：属性必须归属到一个已存在的模型
3. **删除规则**：删除属性会级联删除使用该属性作为参数的方法参数记录
4. **编码规则**：属性编码自动生成，格式为模型编码 + 属性名，如 `MODEL-001_username`

### 2.4 方法管理模块

#### 2.4.1 功能概述

方法是模型的行为定义，方法的入参和出参必须从同一模型下的属性中选择。

#### 2.4.2 功能点

| 功能点 | 描述 | 操作路径 |
|--------|------|----------|
| 方法列表 | 展示指定模型下的所有方法 | /models/{id}/methods |
| 创建方法 | 创建新方法，配置入参和出参 | /models/{id}/methods/create |
| 编辑方法 | 修改方法信息和参数配置 | /models/{id}/methods/{id}/edit |
| 删除方法 | 删除方法及其关联的参数 | /models/{id}/methods/{id}/delete |

#### 2.4.3 参数配置

| 参数类型 | 说明 |
|----------|------|
| INPUT | 入参，方法的输入参数 |
| OUTPUT | 出参，方法的返回结果 |

#### 2.4.4 业务规则

1. **需求关联规则**：创建方法时必须关联一个 `APPROVED` 状态的需求
2. **模型归属规则**：方法必须归属到一个已存在的模型
3. **参数来源规则**：方法的入参和出参必须从同一模型下已创建的属性中选择
4. **参数唯一性规则**：同一个属性在同一个方法中不能同时作为入参和出参
5. **删除规则**：删除方法会级联删除其关联的方法参数记录
6. **编码规则**：方法编码自动生成，格式为模型编码 + 方法名，如 `MODEL-001_login`

| REFUND_COMPLETED | 退款完成 |
| USER_REGISTERED | 用户注册 |
| USER_LOGIN | 用户登录 |

#### 2.5.4 事件状态

| 状态 | 说明 |
|------|------|
| SUCCESS | 成功 |
| FAILED | 失败 |
| PENDING | 处理中 |

#### 2.5.5 业务规则

3. **数量规则**：数量字段默认为0，只支持非负整数

### 2.6 业务流程建模模块

#### 2.6.1 功能概述

业务流程建模模块基于BPMN 2.0标准，提供可视化的业务流程图设计能力，支持将流程节点与业务模型进行绑定，实现业务流程与数据模型的关联追溯。

#### 2.6.2 功能点

| 功能点 | 描述 | 操作路径 |
|--------|------|----------|
| 流程列表 | 展示所有业务流程，支持搜索和筛选 | /processes |
| 创建流程 | 创建新的业务流程，填写基本信息 | /processes/create |
| 编辑流程 | 编辑流程基本信息 | /processes/{id}/edit |
| 流程设计器 | 使用BPMN编辑器设计流程图 | /processes/{id}/design |
| 流程详情 | 查看流程详情、版本历史和节点绑定 | /processes/{id} |
| 删除流程 | 删除业务流程及其相关版本 | /processes/{id}/delete |
| 版本回滚 | 将流程回滚到历史版本 | /processes/{id}/rollback |

#### 2.6.3 流程状态流转

```
DRAFT (草稿)
    │
    ├─→ 启用 → ACTIVE (启用中)
    │         │
    │         └─→ 归档 → ARCHIVED (已归档)
    │
    └─→ 直接删除
```

#### 2.6.4 BPMN元素支持

| 元素类型 | 说明 | 绑定能力 |
|----------|------|----------|
| BPMN:Task | 普通任务 | 可绑定模型 |
| BPMN:UserTask | 用户任务 | 可绑定模型 |
| BPMN:ServiceTask | 服务任务 | 可绑定模型 |
| BPMN:SubProcess | 子流程 | 可绑定模型 |
| BPMN:StartEvent | 开始事件 | - |
| BPMN:EndEvent | 结束事件 | - |
| BPMN:Gateway | 网关 | - |
| BPMN:SequenceFlow | 顺序流 | - |

#### 2.6.5 业务规则

1. **版本管理规则**：每次保存流程设计都会创建新版本
2. **节点绑定规则**：任务类型节点（Task/UserTask/ServiceTask/SubProcess）可绑定业务模型
3. **绑定约束**：同一节点可绑定多个模型
4. **删除规则**：删除流程会级联删除所有版本和节点绑定
5. **状态规则**：只有DRAFT状态的流程可以进行编辑和设计

## 3. 业务流程设计

### 3.1 模型创建完整流程

```
用户登录系统
    │
    ▼
创建需求 ──→ 填写需求信息 ──→ 提交审批
    │
    ▼
审批需求 ──→ 审批通过 (APPROVED)
    │
    ▼
创建模型 ──→ 关联已审批的需求 ──→ 保存模型
    │
    ▼
创建属性 ──→ 选择模型 ──→ 关联需求 ──→ 选择数据类型 ──→ 保存属性
    │
    ▼
创建方法 ──→ 选择模型 ──→ 关联需求 ──→ 配置入参(从属性选择) ──→ 配置出参(从属性选择) ──→ 保存方法
```

### 3.2 需求审批流程

```
创建需求 (DRAFT)
    │
    ├─→ 编辑需求
    │
    └─→ 提交审批 ──→ 进入审批队列 (PENDING)
                          │
                          ├─→ 审批通过 ──→ APPROVED (可被关联)
                          │
                          └─→ 审批拒绝 ──→ REJECTED (可重新编辑后再次提交)
```

### 3.3 方法参数配置流程

```
选择属性列表 (同一模型下的所有属性)
    │
    ▼
选择入参属性 ──→ 添加到入参列表 ──→ 设置排序序号
    │
    ▼
选择出参属性 ──→ 添加到出参列表 ──→ 设置排序序号
    │
    ▼
保存方法参数配置
```

### 3.4 BPMN业务流程建模流程

```
创建业务流程 (填写名称、编码、描述)
    │
    ▼
进入流程设计器 ──→ 使用BPMN编辑器绘制流程图
    │
    ├── 添加开始事件 (StartEvent)
    ├── 添加任务节点 (Task/UserTask/ServiceTask)
    ├── 添加网关 (Gateway)
    ├── 添加结束事件 (EndEvent)
    └── 连接节点 (SequenceFlow)
    │
    ▼
为任务节点绑定业务模型
    │
    ▼
保存流程 ──→ 自动创建版本
    │
    ▼
流程管理 (查看历史版本、回滚、启用/归档)
```

## 4. 数据关系设计

### 4.1 核心数据关系

| 关系 | 说明 | 约束 |
|------|------|------|
| 需求 → 模型 | 一个需求可被多个模型引用 | 需求必须是APPROVED状态 |
| 模型 → 属性 | 一个模型包含多个属性 | 属性必须关联需求 |
| 模型 → 方法 | 一个模型包含多个方法 | 方法必须关联需求 |
| 属性 → 方法参数 | 一个属性可被多个方法参数引用 | 参数类型为INPUT或OUTPUT |
| 方法 → 方法参数 | 一个方法包含多个参数 | 参数必须来自同一模型的属性 |
| 流程 → 流程版本 | 一个流程包含多个版本 | 每次保存创建新版本 |
| 流程 → 节点绑定 | 一个流程包含多个节点绑定 | 任务节点可绑定模型 |
| 流程节点 → 模型 | 一个节点可绑定多个模型 | 节点类型为Task/UserTask等 |

### 4.2 数据约束矩阵

| 操作 | 需求状态 | 模型状态 | 属性状态 | 方法状态 | 允许操作 |
|------|----------|----------|----------|----------|----------|
| 创建模型 | APPROVED | - | - | - | 是 |
| 创建属性 | APPROVED | 存在 | - | - | 是 |
| 创建方法 | APPROVED | 存在 | 存在 | - | 是 |
| 删除需求 | 未关联 | - | - | - | 是 |
| 删除需求 | 已关联 | 存在 | 存在 | 存在 | 否 |
| 删除模型 | - | 存在 | 存在 | 存在 | 是(级联删除) |
