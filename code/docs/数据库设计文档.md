# Z-Model 模型管理系统 - 数据库设计文档

## 1. 数据库概述

### 1.1 数据库选型

本系统采用 **MySQL 8.0+** 作为数据库管理系统，选择理由如下：

| 考量因素 | 说明 |
|----------|------|
| 性能 | MySQL 8.0 提供了更好的查询性能和并发处理能力 |
| JSON支持 | 原生支持JSON数据类型，适合存储事件元数据 |
| 事务支持 | 完整的ACID事务支持，保证数据一致性 |
| 社区成熟 | 成熟的社区生态和丰富的工具支持 |
| 兼容性 | 与Spring Boot JPA完美集成 |

### 1.2 数据库命名规范

| 对象类型 | 命名规则 | 示例 |
|----------|----------|------|
| 表名 | 小写英文，下划线分隔 | `requirement`, `model_requirement` |
| 字段名 | 小写英文，下划线分隔 | `model_id`, `data_type` |
| 主键 | `id`，VARCHAR(36)，UUID格式 | - |
| 外键 | `表名_id`格式 | `model_id`, `requirement_id` |
| 索引 | `idx_表名_字段名` | `idx_property_model_id` |
| 唯一键 | `uk_表名_字段名` | `uk_requirement_code` |

### 1.3 字符集与排序规则

- **字符集**: `utf8mb4`（支持完整的Unicode字符，包括emoji）
- **排序规则**: `utf8mb4_unicode_ci`（支持中文排序）

## 2. 数据库表设计

### 2.1 需求表 (requirement)

**用途**: 存储需求信息，支持主需求与子需求的层级关系。子需求只能通过模型字段或方法的关联描述创建。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | VARCHAR(36) | PRIMARY KEY | 主键ID，UUID格式 |
| name | VARCHAR(100) | NOT NULL | 需求名称 |
| code | VARCHAR(50) | UNIQUE | 需求编号，系统自动生成 |
| description | LONGTEXT | NULL | 需求描述(富文本HTML格式) |
| status | VARCHAR(20) | DEFAULT 'DRAFT' | 状态：DRAFT(草稿)/PENDING(待审批)/APPROVED(已批准)/REJECTED(已拒绝) |
| priority | VARCHAR(20) | DEFAULT 'MEDIUM' | 优先级：LOW(低)/MEDIUM(中)/HIGH(高)/CRITICAL(紧急) |
| requirement_type | VARCHAR(10) | DEFAULT 'MAIN' | 需求类型：MAIN(主需求)/SUB(子需求) |
| parent_id | VARCHAR(36) | NULL, FOREIGN KEY | 父需求ID，子需求关联主需求 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

**需求类型说明**:

| 值 | 说明 | 创建方式 |
|----|------|----------|
| MAIN | 主需求 | 用户手动创建 |
| SUB | 子需求 | 只能通过模型字段或方法的关联描述自动创建 |

**索引**:
- `uk_requirement_code` (唯一索引)
- `idx_requirement_status` (普通索引)
- `idx_requirement_priority` (普通索引)
- `idx_parent_id` (普通索引，用于查询子需求)
- `idx_requirement_type` (普通索引，用于筛选主/子需求)

**外键约束**:
- `parent_id` → `requirement(id)` ON DELETE CASCADE

### 2.2 模型表 (model)

**用途**: 存储模型信息，模型是属性和方法的容器

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | VARCHAR(36) | PRIMARY KEY | 主键ID，UUID格式 |
| name | VARCHAR(100) | NOT NULL | 模型名称 |
| code | VARCHAR(50) | UNIQUE | 模型编号，系统自动生成 |
| description | LONGTEXT | NULL | 模型描述(富文本HTML格式) |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

**索引**:
- `uk_model_code` (唯一索引)

---

### 2.3 模型需求关联表 (model_requirement)

**用途**: 建立模型与主需求的多对多关联关系

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | VARCHAR(36) | PRIMARY KEY | 主键ID，UUID格式 |
| model_id | VARCHAR(36) | NOT NULL, FOREIGN KEY | 模型ID，关联model(id) |
| requirement_id | VARCHAR(36) | NOT NULL, FOREIGN KEY | 需求ID，关联requirement(id) |

**索引**:
- `uk_model_requirement` (唯一索引: model_id + requirement_id)
- `idx_model_requirement_model` (普通索引)
- `idx_model_requirement_requirement` (普通索引)

**外键约束**:
- `model_id` → `model(id)` ON DELETE CASCADE
- `requirement_id` → `requirement(id)` ON DELETE CASCADE

---

### 2.4 属性表 (property)

**用途**: 存储模型的属性定义，属性是方法参数的来源，属性关联的是子需求

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | VARCHAR(36) | PRIMARY KEY | 主键ID，UUID格式 |
| name | VARCHAR(100) | NOT NULL | 属性名称 |
| code | VARCHAR(50) | NULL | 属性编码，系统自动生成 |
| data_type | VARCHAR(20) | NOT NULL | 数据类型 |
| model_id | VARCHAR(36) | NOT NULL, FOREIGN KEY | 所属模型ID |
| requirement_id | VARCHAR(36) | NULL, FOREIGN KEY | 关联子需求ID |
| required | BOOLEAN | DEFAULT FALSE | 是否必填 |
| default_value | VARCHAR(255) | NULL | 默认值 |
| description | LONGTEXT | NULL | 属性描述(富文本HTML格式) |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

**数据类型枚举 (data_type)**:

| 值 | 说明 |
|----|------|
| STRING | 字符串 |
| INTEGER | 整数 |
| LONG | 长整数 |
| DOUBLE | 浮点数 |
| BOOLEAN | 布尔值 |
| DATE | 日期 |
| DATETIME | 日期时间 |
| ENUM | 枚举 |
| OBJECT | 对象 |
| ARRAY | 数组 |

**索引**:
- `idx_property_model_id` (普通索引)
- `idx_property_requirement_id` (普通索引)

**外键约束**:
- `model_id` → `model(id)` ON DELETE CASCADE
- `requirement_id` → `requirement(id)` ON DELETE SET NULL

### 2.6 方法参数表 (method_param)

**用途**: 存储方法的参数定义，参数必须从属性中选择

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | VARCHAR(36) | PRIMARY KEY | 主键ID，UUID格式 |
| method_id | VARCHAR(36) | NOT NULL, FOREIGN KEY | 方法ID |
| property_id | VARCHAR(36) | NOT NULL, FOREIGN KEY | 属性ID（参数来源） |
| param_type | VARCHAR(20) | NOT NULL | 参数类型：INPUT(入参)/OUTPUT(出参) |
| sort_order | INT | DEFAULT 0 | 排序序号 |

**索引**:
- `uk_method_property` (唯一索引: method_id + property_id + param_type)
- `idx_method_param_method` (普通索引)
- `idx_method_param_property` (普通索引)

**外键约束**:
- `method_id` → `method(id)` ON DELETE CASCADE
- `property_id` → `property(id)` ON DELETE CASCADE

---

### 2.7 业务流程表 (bpmn_process)

**用途**: 存储BPMN业务流程定义，支持版本管理和模型绑定

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | VARCHAR(36) | PRIMARY KEY | 主键ID，UUID格式 |
| name | VARCHAR(100) | NOT NULL | 流程名称 |
| code | VARCHAR(50) | UNIQUE | 流程编号，系统自动生成 |
| description | LONGTEXT | NULL | 流程描述(富文本HTML格式) |
| bpmn_xml | LONGTEXT | NULL | BPMN 2.0 XML定义 |
| version | INT | DEFAULT 1 | 当前版本号 |
| status | VARCHAR(20) | DEFAULT 'DRAFT' | 状态：DRAFT(草稿)/ACTIVE(启用中)/ARCHIVED(已归档) |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

**流程状态枚举 (status)**:

| 值 | 说明 |
|----|------|
| DRAFT | 草稿，可编辑 |
| ACTIVE | 启用中，已发布使用 |
| ARCHIVED | 已归档，不再使用 |

**索引**:
- `uk_bpmn_process_code` (唯一索引)
- `idx_bpmn_process_status` (普通索引)

---

### 2.8 业务流程版本表 (bpmn_process_version)

**用途**: 存储业务流程的历史版本，支持版本回滚

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | VARCHAR(36) | PRIMARY KEY | 主键ID，UUID格式 |
| process_id | VARCHAR(36) | NOT NULL, FOREIGN KEY | 流程ID，关联bpmn_process(id) |
| version | INT | NOT NULL | 版本号 |
| bpmn_xml | LONGTEXT | NOT NULL | 该版本的BPMN 2.0 XML定义 |
| change_note | VARCHAR(500) | NULL | 变更说明 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**索引**:
- `uk_process_version` (唯一索引: process_id + version)
- `idx_process_version_process` (普通索引)

**外键约束**:
- `process_id` → `bpmn_process(id)` ON DELETE CASCADE

---

### 2.9 流程节点模型绑定表 (process_node_model)

**用途**: 建立流程节点与业务模型的关联，实现流程节点的业务含义

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | VARCHAR(36) | PRIMARY KEY | 主键ID，UUID格式 |
| process_id | VARCHAR(36) | NOT NULL, FOREIGN KEY | 流程ID，关联bpmn_process(id) |
| node_id | VARCHAR(100) | NOT NULL | BPMN节点ID（XML中的元素ID） |
| model_id | VARCHAR(36) | NOT NULL, FOREIGN KEY | 关联的业务模型ID，关联model(id) |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**索引**:
- `uk_process_node_model` (唯一索引: process_id + node_id + model_id)
- `idx_process_node_model_process` (普通索引)
- `idx_process_node_model_model` (普通索引)

**外键约束**:
- `process_id` → `bpmn_process(id)` ON DELETE CASCADE
- `model_id` → `model(id)` ON DELETE CASCADE

| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

**事件类型枚举 (event_type)**:

|----|------|

| ORDER_COMPLETED | 订单完成 |
| PAYMENT_SUCCESS | 支付成功 |
| PAYMENT_FAILED | 支付失败 |
| REFUND_REQUESTED | 退款申请 |
| REFUND_COMPLETED | 退款完成 |
| USER_REGISTERED | 用户注册 |
| USER_LOGIN | 用户登录 |
| USER_LOGOUT | 用户登出 |
| PRODUCT_VIEWED | 商品浏览 |
| PRODUCT_ADDED | 商品加入购物车 |
| INVENTORY_LOW | 库存预警 |
| SYSTEM_ERROR | 系统错误 |
| SYSTEM_WARNING | 系统警告 |

**索引**:
- `idx_event_model_id` (普通索引)
- `idx_event_event_type` (普通索引)
- `idx_event_status` (普通索引)
- `idx_event_event_time` (普通索引)

**外键约束**:
- `model_id` → `model(id)` ON DELETE SET NULL

## 4. 表关系说明

| 关系 | 主表 | 从表 | 关系类型 | 说明 |
|------|------|------|----------|------|
| 模型-主需求 | model | model_requirement | 一对多 | 一个模型关联多个主需求 |
| 主需求-模型 | requirement(MAIN) | model_requirement | 一对多 | 一个主需求可被多个模型引用 |
| 主需求-子需求 | requirement(MAIN) | requirement(SUB) | 一对多 | 一个主需求包含多个子需求 |
| 子需求-属性 | requirement(SUB) | property | 一对多 | 子需求关联属性描述 |
| 子需求-方法 | requirement(SUB) | method | 一对多 | 子需求关联方法描述 |
| 模型-属性 | model | property | 一对多 | 一个模型包含多个属性 |
| 模型-方法 | model | method | 一对多 | 一个模型包含多个方法 |
| 方法-参数 | method | method_param | 一对多 | 一个方法包含多个参数 |
| 参数-属性 | method_param | property | 多对一 | 参数引用一个属性 |
| 事件-模型 | event | model | 多对一 | 事件关联一个模型 |
| 流程-版本 | bpmn_process | bpmn_process_version | 一对多 | 一个流程有多个版本 |
| 流程-节点绑定 | bpmn_process | process_node_model | 一对多 | 一个流程有多个节点绑定 |
| 节点绑定-模型 | process_node_model | model | 多对一 | 绑定引用一个模型 |

## 5. 需求层级关系设计

### 5.1 主需求与子需求的关系

```
主需求 (REQ-001) - 用户管理需求
├── 子需求 (REQ-001-01) - [用户名] 属性描述
├── 子需求 (REQ-001-02) - [密码] 属性描述
├── 子需求 (REQ-001-03) - [邮箱] 属性描述
├── 子需求 (REQ-001-04) - [登录] 方法描述
└── 子需求 (REQ-001-05) - [注册] 方法描述
```

### 5.2 子需求创建规则

| 规则 | 说明 |
|------|------|
| 创建时机 | 创建或编辑模型属性/方法时 |
| 创建条件 | 选择主需求并填写描述 |
| 命名规则 | `[属性/方法名称] 属性描述` 或 `[方法名称] 方法描述` |
| 编号规则 | 主需求编号 + 序号，如 REQ-001-01 |
| 状态继承 | 继承主需求的状态和优先级 |
| 手动创建 | 禁止用户手动创建子需求 |

## 9. 性能优化建议

### 9.1 索引优化

| 表名 | 建议索引 | 用途 |
|------|----------|------|
| requirement | idx_status_priority | 按状态和优先级查询 |
| requirement | idx_parent_id | 查询主需求下的子需求 |
| property | idx_model_data_type | 按模型和数据类型查询 |
| method | idx_model_name | 按模型和名称查询 |
| event | idx_event_time_type | 按时间和类型查询事件 |
| event | idx_model_status | 按模型和状态查询 |

### 9.2 分区建议

对于事件表(event)，建议按时间分区：

```sql
ALTER TABLE event PARTITION BY RANGE (TO_DAYS(event_time)) (
  PARTITION p202401 VALUES LESS THAN (TO_DAYS('2024-02-01')),
  PARTITION p202402 VALUES LESS THAN (TO_DAYS('2024-03-01')),
  PARTITION p202403 VALUES LESS THAN (TO_DAYS('2024-04-01'))
);
```

### 9.3 查询优化

- 使用JOIN代替子查询
- 避免SELECT *，只查询需要的字段
- 对大数据量查询使用LIMIT分页
- 使用EXPLAIN分析慢查询
